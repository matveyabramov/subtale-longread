## 2. Общий UX-контракт R

1. Десять narrative sections: Hero → Experiment → Emptiness → Elephant → Blind zones explorer → Movies → Vocab → Blind-spot-scene → What-to-do → Footer. В explorer показана одна из восьми A/B-композиций. По актуальному D02 Experiment — один закреплённый полноэкранный слой с тремя состояниями React. В потоке между Hero и Emptiness остаётся один постоянный слот высотой viewport с непрозрачной декоративной подложкой Result без контролов; в fullscreen-слое одновременно смонтирован один активный шаг. Переходы между шагами выполняются кнопками без прокрутки документа.
2. За пределами Hero gate I01 и управляемых экранов Experiment I02 прокруткой управляет браузер без pin/snap. Hero удерживает первое вступление до выбора/безопасного выхода. Пока Experiment открыт, общая блокировка с fixed body сохраняет место страницы и поддерживает iOS Safari; при недостатке высоты прокручивается только активный шаг. Help использует вложенную блокировку того же владельца. При выходе/pagehide/unmount стили и прокрутка обязательно восстанавливаются. Прямые якоря и Back/Forward обходят удержание. Оглавление доступно вне Experiment; внутри него контрол скрыт и исключён из фокуса. Закрытые поп-апы не оставляют document scroll lock; обработчики Experiment снимаются при размонтировании.
3. Ссылка меняет место чтения, кнопка — состояние. Активация кнопок: click/tap, Enter/Space; действие на release, отменённый жест и уход пальца не активируют его. Для навигационных ссылок — Enter и стандартное поведение браузера. Touch не зависит от hover; при mouse hover допустим лишь feedback, не обязательное раскрытие смысла.
4. Видимый `focus-visible`, логичный DOM-порядок, имя каждого контрола и различимость состояний помимо цвета. Рекомендованный hit area ≥44×44 CSS px без сдвига Figma-геометрии; проверить пересечения, особенно нижних текстовых ссылок. Увеличение текста/zoom не обрезает управление и объяснения.
5. Обычный scroll не перемещает focus и не объявляется live-region. Открытие полноэкранного Experiment переводит focus внутрь активного шага. Явный переход к секции фокусирует её заголовок с временным `tabindex=-1`; обновление контрола оставляет focus на нём. При скрытии панели focus сначала переводится на сохраняющийся контрол. Скрытые панели исключены из tab-порядка и accessibility tree, а не только прозрачны.
6. Семантическое состояние меняется независимо от анимации. Повторная активация задаёт новую цель, не ставится в очередь. Новый выбор категории, уход со страницы, смена reduced-motion и размонтирование отменяют декоративные переходы; старые callbacks не возвращают предыдущее состояние.
7. Хранение — память текущей страницы. Scroll away/back сохраняет выбор категории, A/B и прогресс опыта; явный reset меняет только свой модуль. Только настоящий reload очищает hash через replaceState, сохраняет path/query, возвращает на Hero и сбрасывает Hero/Experiment. Свежие прямые ссылки, обычные hash-переходы и Back/Forward не сбрасывают состояние/маршрут; восстановление истории остаётся нативным. Не добавлять localStorage, cookies, историю каждого toggle или глобальный reset.
8. Ссылки на разделы имеют стабильные якоря R: `#hero`, `#experiment`, `#experiment-instructions`, `#experiment-target`, `#experiment-result`, `#emptiness`, `#elephant`, `#blind-zones`, `#movies`, `#vocab`, `#blind-spot-scene`, `#what-to-do`, `#footer`. Внутренние toggles hash не меняют; явные якоря совместимы с Back/Forward. При `hashchange`/history traversal не перезапускать опыт и видео. Системное восстановление scroll не перебивается автоскроллом; прямой hash не требует прохождения предыдущих экранов.
9. Пока загрузился только A, не показывать пустой B и не отключать всё чтение: декодировать требуемый B, показать локальный текстовый статус загрузки; последний запрос побеждает. При ошибке сохранить доступное изображение и объяснение, предложить Retry. Тексты loading/error/retry — служебные предложения, не Figma copy; включены в D09. Место изображения зарезервировано по измеренной геометрии.
10. У каждого модуля есть статически читаемая основа. Ошибка GSAP/отключённое движение не скрывает текст и контролы. Требование работы всего React-приложения без JavaScript не утверждалось; не выдавать CSR-shell за полноценный no-JS fallback.

## 3. Hero, оглавление и Experiment

### I01 — Hero `10:472`

**F:** headline/collage, CTA, «Оглавление» и отдельная композиция вступительного поп-апа с «Начать» / «Пропустить». Существующие тексты сохраняются дословно. Утверждённые Hero-фреймы: 1920 `10:472`, 1440 `69:1182`, 768 `73:7145`, 390 `79:12334` (файл выше). Размеры и слои брать из соответствующего кадра; поп-ап отделён от начальной композиции.

**Актуальный контракт D01 (2026-10-25):** первоначально Hero без поп-апа. Первая попытка прокрутки вниз открывает вступление и удерживает переход прокруткой к следующей секции до выбора. «Начать» → `#experiment-instructions`, «Пропустить» → `#emptiness`; оба действия закрывают поп-ап, снимают удержание и фокусируют заголовок цели. Прямой CTA ведёт к инструкциям и также завершает вступление. После выбора Hero больше не удерживает scroll; отдельное управление Experiment описано в I02. Возвращение в Hero не открывает вступление повторно. Состояние живёт до reload, без persistent storage.

**Ввод и доступность (требования Stage 3):** одинаковый gate для wheel, touch-жеста прокрутки и клавиатурной прокрутки вниз (ArrowDown / PageDown / Space / End); не перехватывать ввод в контролах, модифицированные сочетания, zoom и жесты назад. Поп-ап — именованный dialog с focus внутри, доступными Start/Skip и локальным Tab-порядком; фон неактивен только пока он открыт. Внутренний scroll длинного поп-апа, все его кнопки, zoom, смена ориентации и короткий viewport остаются доступны. Escape/штатная команда закрытия AT — безопасный отказ от вступления: закрыть, снять удержание, оставить на Hero и вернуть focus к CTA; gate не открывается снова. Это аварийный выход, не скрытый принудительный выбор Experiment. При ошибке открытия/размонтировании/уходе со страницы блокировка обязательно снимается; никаких циклов повторного открытия, таймеров ожидания и накопленного scroll-рывка после выбора. Прямые hash-ссылки за Hero и Back/Forward не заставляют проходить вступление и не перебиваются gate.

**Reload — актуальное уточнение Navigation Fix (2026-10-28):** только `PerformanceNavigationTiming.type=reload` очищает hash через `history.replaceState`, сохраняя path/query, возвращает Hero и сбрасывает состояния. На время начального восстановления Safari используется `scrollRestoration=manual`, затем возвращается прежнее значение; коррекция после pageshow не перебивает уже выбранный пользователем новый якорь. Обычные hash-переходы и Back/Forward не запускают reset. Focus перемещается и после pointer/touch, но обводка отображается только после клавиатурного ввода. На Mobile низ вступления совпадает с CTA: `max(12px, safe-area-inset-bottom)`.

**Высота:** композицию привязывать к viewport там, где это позволяет утверждённый кадр, но short viewport / увеличение текста не обрезают контент и выходы. Будущий gate удерживает границу секции, а не требует спрятать содержание в жёстком `100vh`. В Stage 2.1 нет обработчиков прокрутки, открытия поп-апа или scroll lock.

**Оглавление R:** disclosure с кнопкой `aria-expanded`/`aria-controls` и списком якорных ссылок на narrative sections. Первоначально закрыто; повторный click и Escape закрывают, Escape возвращает focus кнопке; выбор пункта закрывает и фокусирует целевой заголовок. Внешний click закрывает без принудительного focus, если пользователь уже выбрал другую цель. Не focus trap. Разметка/позиция открытой панели и подписи пунктов не спроектированы — D03, без самовольного меню поверх композиции. Новые окна по умолчанию не нужны.

### I02 — Experiment `10:718`, `10:730`, `10:760`

**F:** инструкции требуют закрыть левый глаз, правым смотреть на крестик, менять физическую дистанцию до экрана. Результат прямо говорит, что точка всё время оставалась на экране; предусмотрено сообщение о том, что эффект может не сработать. Это перцептивный опыт, не компьютерная проверка зрения и не анимационный трюк.

**Неизменный инвариант:** не мерцать, не скрывать/затемнять/двигать точку, не отслеживать глаза/камеру и не «вычислять успех». Нет таймера, балла, обязательной дистанции или признака неудачи. Cross group `10:732` в (610,490), 100×100; dot `10:735` в (1210,490), 100×100. На 1920px сохранить эти слоты; Figma vector paths, толщины и дробные координаты — в VECTOR_ASSET_SOURCE. У меньших экранов эффект зависит от физического размера; это основание для честного skip, а не автоматического масштабирования опыта.

**Approved / D02 — Boundary Fix, 2026-10-28:** Experiment — один portal-layer `position: fixed` с высотой `100dvh` / `100vh` fallback и safe areas. Instructions / Target / Result — состояния React; одновременно смонтирован только активный шаг. В потоке — один стабильный слот `100dvh` с `100vh` fallback и неинтерактивным Result-фоном; трёх отдельных прокручиваемых шагов нет. Hero остаётся в обычном потоке и не скрывается. Вход из Hero/оглавления/прямого hash открывает нужное состояние. Кнопки вперёд/назад меняют state и hash без `scrollTo`/`scrollIntoView` между шагами. Wheel/touch/клавиатура прокручивают только содержимое активного шага, если оно не помещается. Пока слой открыт, фон inert, body закреплён с сохранённой позицией, оглавление скрыто/inert. На выходе стили восстанавливаются и выбирается целевой якорь документа. Прямые hash и Back/Forward открывают/закрывают слой без сброса outcome. Wheel/touch/клавиша вверх через начало Emptiness проверяет нижнюю границу слота и синхронно открывает Result до стандартной прокрутки браузера. Остаточная инерция из более глубокой позиции подстрахована проверкой входа в непрозрачный слот; Hero отделён от Emptiness целым экраном. Один жест не открывает слой повторно. На выходе Result → Emptiness блокировка снимается, позиция берётся из фактической границы Emptiness после разблокировки, без CSS-отступов. Instructions Back закрывает слой на Hero; следующая прокрутка вниз открывает Instructions без повторного вступления. Нет snapping, анимаций, таймеров или скрытия стимулов. Тексты, включая исходную scroll-инструкцию, сохранены по прямому ограничению пользователя.

Шаг занимает весь закреплённый слой; CSS dvh и container/media height queries обслуживают изменения высоты без JS-расчётов visualViewport, компенсационных смещений и позиционирования через scroll. На коротких устройствах доступна внутренняя прокрутка без обрезки управления. Клавиатурная обводка сохраняется у интерактивных контролов; неинтерактивные заголовки/Target служат именованными целями фокуса без декоративной рамки. Standalone-ссылки Desktop/Tablet сохраняют кегль «Оглавления» (18px на 1920+, 20px на 601–1919px); Mobile-типографика не меняется.

**Help D04 (уточнение 2026-10-25):** «Не получается?» открывает предусмотренный Figma поп-ап с инструкцией, а не постоянную встроенную disclosure-панель. Состав, тексты и визуал — из help-фрейма Figma. Предусмотреть доступное имя, вход focus в поп-ап, закрытие Escape/штатным контролом/click или tap снаружи и возврат focus к триггеру; для модального представления — `aria-modal`, неактивный фон и локальный focus trap только на время открытия. Skip остаётся доступен без успешного эффекта. Ни открытие, ни закрытие помощи не двигают крестик и точку. Нажатие должно начинаться и завершаться снаружи: click внутри и перетаскивание изнутри не закрывают панель. Длинный текст прокручивается внутри поп-апа. Реализация Stage 3.3 — Awaiting Review.

Mouse, touch и keyboard используют одинаковые переходы. Точка/крест — не buttons и не tab stops; доступное описание передаёт инструкцию и честную возможность продолжить без опыта. Screen reader не должен «доказывать исчезновение»: объяснение и result доступны напрямую. Визуальный эффект может быть недоступен пользователю; это не препятствует истории. Reduced motion не меняет экспериментальные стимулы: они всегда неподвижны. Явные якоря мгновенные в базовом варианте; smooth scroll отдельно не предлагается.

Не добавлять автоматические панорамирование, zoom и монтаж к существующим MP4.

**Accessibility / D10:** доступное имя каждого player — фильм и case, controls доступны клавиатурой. Существующая реплика на странице не равна полным captions/транскрипту. Переключение preference во время playback приостанавливает клип; только новый явный Play продолжает. До медиа-материалов и browser QA доступность видео остаётся открытым пунктом, а не заявленным соответствием стандарту.

**React** владеет смыслом: выбор, outcome, open/closed, доступность, asset readiness, media events, focus и конечная цель. Использовать локальные reducers там, где есть связанные переходы, без дополнительной FSM-библиотеки по умолчанию. Начальная модель данных explorer — четыре записи `id`, A/B frame IDs, artwork mapping, существующая подпись вопроса, согласованное описание; фильмы — пять записей из §5. Не хранить duplicate DOM для восьми полных экранов.

**CSS Modules** владеют Figma layout, типографикой, цветом, crop/masks, stacking, clipping, статическими endpoints, focus и простыми interruptible transitions. Art wrapper сохраняет design transform/crop; внешний motion-wrapper, если нужен, владеет только добавочным transform/opacity. Не давать React inline-style, CSS transition и GSAP одновременно писать один и тот же transform. Не анимировать layout-геометрию текста, шрифты, Figma blur/filters или texture blend.

**GSAP** — только опциональная координация нескольких декоративных слоёв/согласованного таймлайна. Простому rotate Pun или opacity не нужна обязательная timeline. **ScrollTrigger** не требуется базовому контракту; IntersectionObserver достаточно для одноразового fade. Если позже одобрена scroll-связь — отдельный ticket с измеримыми start/end, reset/exit и reduced motion; pin/scrub не включать автоматически. Не добавлять Motion/WAAPI/framework из навыка только по факту его чтения.

**Lifecycle:** каждый effect/timeline/observer/listener создаётся локально и очищается при смене категории, policy и unmount; выдерживает повторный mount в React StrictMode. При отмене — конечный DOM отражает последнюю React-цель. В GSAP использовать scoped context/revert; callbacks проверяют актуальность запроса. DOM measurements — после шрифтов и нужных images, без чтения layout на каждом scroll. В reduced motion не создавать ненужные timeline/scroll listeners.

**Загрузка:** Hero и актуальный первый screen получают приоритет по будущим измерениям Stage 1; тяжёлый Idiom (~10.94 MB package) не означает предзагрузку всех архивов. Загружать текущую композицию и требуемую альтернативу при приближении/намерении; reuse по delivery URL/imageHash. Source-only fills не попадут в runtime import. Постеры lazy вне первого viewport; пять видео не загружаются одновременно. Визуальную готовность/ошибку не привязывать к окончанию анимации.
